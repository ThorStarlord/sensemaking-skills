## Alternatives and selected transformation

A: keep current module and aliases only; no immediate integration risk but every new source-only consumer continues to depend on the higher-level knowledge-construction module. B: extract the coherent source boundary into source_access.py and redirect the four real source-only consumers to it; preserve old entrypoints as explicit compatibility aliases, and retain the snapshot builder's use of the same definitions. C: redesign all Git read layers, snapshot/cache internals, and source materialization together; reject for this bounded responsibility because the observed issue is dependency direction, not a warrant to change source bytes or rewrite operational guards. D: inject all source readers into every consumer; could permit alternative materialization mechanisms but would unnecessarily expand interfaces and duplicate wiring for current exact-source use. Select reversible BUILD B. The existing imported functions are moved verbatim; no changes to safety or Git behavior are implied by the move. Preserve the current knowledge-plane component as the builder/knowledge owner; declare a distinct component owning only the new source-access file. This is scoped separation, not a claim that every consumer of knowledge_sources.py has been decoupled.
