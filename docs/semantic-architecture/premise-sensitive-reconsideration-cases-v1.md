## CASE-P1: Qualified retrieval premise, unchanged strategic direction

**Original purpose:** Later engineering episodes should benefit from reviewed, durable product/architecture understanding, not merely generate ontology rows.

**A: What was originally judged.** `PATH-1` accretes knowledge through genuine engineering responsibilities; `PATH-2` performs a bounded product-core BOOTSTRAP before accreting. `ASSUMPTION-1` expected separate later sessions to query relevant knowledge. `ASSUMPTION-2` concerned core contracts remaining reachable through auto-loaded instructions. The author preferred `PATH-1` in its contemporary constraints.

**B: What changed.** The author revised the *applicability* of `ASSUMPTION-1`: actual discoverability must exist before a session can query the reviewed knowledge. This is **UNDERSTANDING_CHANGED** concerning the prerequisite, not a proof that nobody can use the knowledge, nor a new owner goal. `ASSUMPTION-2` was confirmed.

**B: What did not change.** The author explicitly selected `CONTINUE` on `PATH-1`, reported `PATH-1/T1 PARTIAL`, and `REAFFIRM`ed the Level-3 strategic direction. No new Level-4 intent or permission to deploy/merge follows.

**Agent's useful answer:** “The reachability assumption warrants targeted source/discovery checks for later-agent contexts. That qualification narrows a predicted mechanism but does not itself defeat the current PATH-1 preference. Inspect whether the target host can actually recover the records before interpreting a lack of reuse as strategy failure. PATH-1 remains selected in the historical reconciliation; future present-day choice requires its own current evidence.”

**Relationship role:** `ASSUMPTION-1` is an expressly listed assumption of `PATH-1`; it is **supporting/decision-relevant**, not established as a logically **necessary** premise for the entire path's value. `ASSUMPTION-2` also occurs with `PATH-2`; mere co-occurrence does not infer identical support, sufficiency, or changed strategy.

## CASE-N1: Nearby but not decision-bearing

**Normative negative control; not an additional historical event.** An indexed graph's `references` edge joins an engineering note to an earlier ADR. The note merely names the ADR as background. A current revision of that ADR should **not** automatically label every referencing decision invalid or causally affected. Report `CONTEXT_ONLY` unless original source supports another exact role. Unknown role is `UNKNOWN`, not `NECESSARY`.

## CASE-N2: No index edge or source accessible

**Normative negative control.** A focused graph neighborhood lacks an edge from premise P to judgment J, while original source documentation is available. The correct action is source re-entry; no edge means `ABSENT_FROM_GRAPH`, not that no dependency exists. If the original source also fails to establish the relationship, return `NOT_ASSESSED`. Preserve truncation and exact current/indexed revisions.

## CASE-N3: Changed code, unchanged strategic intent

**Normative negative control.** A new commit changes the source bytes of an implementation component, while an older strategy decision is still applicable under the same beneficiary/purpose. File drift warrants checking source currentness; it does not by itself grant a new selection, change owner intent, infer causal loss, or reopen Level 3/4. Distinguish `WORLD_CHANGED` from `UNDERSTANDING_CHANGED` and `GOVERNING_INTENT_CHANGED`.

## CASE-O1: New end versus a new way to reach an old end

**Normative exploration, not a newly accepted `poss:` record.** Imagine combining source-pinned possibility history with assumption-scoped reconsideration into a user experience: a repository owner can explore entire *families of futures conditional on assumptions*, not merely read old alternatives. Compare the closest existing `poss:assumption-aware-opportunity-ecology` before claiming novelty. With that record already present this is **RESTATED or an explicit REVISED mechanism**, not automatically a new product goal. If the beneficiary/end differs, explain how and label novelty `NOT_ASSESSED` until the inspected possibility corpus is sufficiently understood.

## Re-entry competency questions

1. Which assumption changed, in which attributed source, and from which exact historical revision to which new assessment?
2. Was the assumption recorded as necessary, supporting, defeating, contextual or unknown **for the specific judgment**? Is that role actually supported by original text?
3. What remained unchanged? Is a current Level-3/4 decision affected, or only a historical author's interpretation?
4. What counterexample or alternative explanation would make the apparent dependence weak?
5. If knowledge is missing from the indexed graph, what original source and scope would need inspection?
6. Which candidate future is **materially different for a beneficiary**, not merely a new implementation mechanism or a duplicate of an earlier `poss:`?
7. Does the question warrant no model change, source-qualified further inquiry, or a genuinely authorized decision—not automatic graph dispatch?

**Evidence ceiling:** These cases demonstrate *documentary reconstruction*, not a fresh independent coding agent, causal graph superiority or validated new product outcome. Source-checked direct documentation is an acceptable successful fallback.
