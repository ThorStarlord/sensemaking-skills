# Semantic Architecture Phase 10 — Common Envelope Results

**Status:** COMPLETE CANDIDATE — pending exact-head repository qualification  
**Experiment:** three additional real-repository reasoning episodes  
**Decision:** **Outcome A — keep `semantic_reasoning_profile` as a companion audit/reconstruction artifact**

## Episodes

| Episode | Reasoning shape | Material profile value | Duplication | Embedding signal |
|---|---|---|---|---|
| Chess Mentor Engine | direct repository diagnosis | compact target/currentness + observed/inferred boundary + unresolved evaluator authority | moderate-high | do not embed wholesale |

## Question-by-question result

### 1. Does the profile reduce duplicated semantic reconstruction?

**Yes, selectively.**

A fresh reader can recover the target snapshot, observed facts, material interpretations, unresolved questions, and non-claims without learning each domain artifact's local vocabulary first. The benefit was strongest when evidence crossed surfaces with different currentness semantics, as in the React exact-SHA handoff plus live PR metadata.

The profile does not eliminate the need to read domain artifacts when making the actual domain decision.

### 2. Does it catch missing currentness/evidence/limits that change decisions?

**Yes, in at least one material episode.**

The React episode required re-querying live PR state rather than treating snapshot-bound handoff prose as current. The profile made the immutable-versus-live evidence boundary explicit and preserved the possibility of off-surface evidence as an uncertainty.

Chess Mentor Engine already had strong claim ceilings, so the profile mainly clarified inference versus observation. ViralFactory's PM artifact already represented the consequential evidence gap.

### 3. Should selected fields be embedded in canonical artifacts?

**Not yet.**

No same missing field was demonstrated in at least two Phase 10 domain artifacts strongly enough to satisfy the preregistered Outcome-B rule.

The reusable pressure is `target/currentness`, but repo-sensemaker and output-reconciler already model it, and PM risk artifacts can preserve their own source/evidence boundary without taking on the whole generic profile.

Embedding now would convert a useful cross-artifact audit representation into duplicate canonical state.

### 4. Does the profile create fake boilerplate?

**It can if made mandatory.**

The ViralFactory episode shows the clearest risk. `risk_analysis` already contains evidence status, evidence refs, unresolved questions, recommendation boundaries, and mitigation semantics. A required second generic representation would encourage agents to restate the same material merely to satisfy another schema.

The current optional companion use avoided that failure.

### 5. What is the coordination overhead?

The experiment did not instrument exact token counts, so no fake precision is reported.

Observed coordination cost is **moderate**: each companion profile requires a second representation of target/currentness, observations, claims, uncertainties, and explicit limits. That cost is justified in currentness-sensitive reconciliation and fresh-context reconstruction, but not obviously justified inside every strong domain artifact.

### 6. Does fresh-context reconstruction improve?

**Qualitatively yes.**

The profiles provide a domain-neutral index into why the episode reached its conclusion and what remains unproven. This is especially valuable for a fresh context that does not yet know `verified/disputed/omitted`, `tiger/paper_tiger/elephant`, or repository-specific milestone vocabulary.

This experiment did not run a blinded human/native-harness reconstruction benchmark, so the result remains qualitative rather than an empirical time/token reduction claim.

## Validator-boundary result

No episode required deterministic semantic judgment. The existing profile validator remained sufficient because it checked representation only and continued to emit:

```text
semantic_truth_established: false
```

The PM `risk_analysis` artifact continued to use its existing specialized validator. No new generic semantic validator or router was needed.

## Phase 10 decision

Choose **Outcome A**:

> Keep `semantic_reasoning_profile` v1 as an optional companion reasoning/audit/reconstruction artifact. Do not embed it wholesale into canonical analytical artifacts and do not promote it into Campaign state.

Use the profile when at least one of these conditions exists:

- reasoning spans multiple artifacts/surfaces with different currentness semantics;
- a fresh context needs a compact warrant/provenance index;
- an experiment/review is comparing reasoning across Skills or domains;
- the canonical artifact's local vocabulary makes cross-domain audit unnecessarily expensive.

Do not require it when a strong domain artifact already represents the decision-changing evidence/currentness/uncertainty/limits and no cross-artifact reconstruction need exists.

## Consequences

### Keep

- `semantic_reasoning_profile` v1 contract;
- standalone representation validator;
- Phase 9 + Phase 10 profiles as dogfood fixtures/evidence;
- explicit semantic-truth non-claim.

### Do not do

- no Campaign artifact admission for the profile;
- no Campaign schema v3 work from this experiment;
- no universal analytical-artifact envelope;
- no central reasoning engine;
- no Repository Semantic Map merely because six episodes now exist;
- no automatic capability selection or semantic routing.

### Future trigger for selective embedding

Reopen Outcome B only if at least two later contrasting domain artifacts repeatedly omit the same decision-changing field and companion reconstruction is insufficient or operationally expensive.
