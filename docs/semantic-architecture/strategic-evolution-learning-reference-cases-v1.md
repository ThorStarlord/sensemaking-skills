## 2. A — Strategic evolution: PATH-1 versus PATH-2 without invented futures

**Original analyzed world, not today's source state.** The A report examines ADR 0031's accepted persistent-knowledge purpose and a then-current source snapshot at `aa13f40`, not the 2026-11-05 ontology implementation. It says the owner asked to observe the Skills, and the repo's accepted strategy supplied the direction question.

**Purpose and beneficiary A-P1:** an agent-assisted repository owner wants later genuinely separate engineering episodes to make better decisions with reviewed product/history knowledge, not merely gain more ontology rows. This is already governed intent; it is **not** an independently discovered new `ProductPossibility`.

**Original capability/limit A-B1:** an authored semantic plane, RECALL/ADD mechanisms and path contracts existed; coverage heavily favored the semantic plane and later-session use was unqualified. A source-read gap is *not by itself* proof of absent product functionality.

**Compared futures:**

- `PATH-1`, **accrete product knowledge through genuine bounded work**: source-check current task, build an actually warranted useful slice, retain non-derivable related knowledge. Conditional benefits: reviewable knowledge grows where engineering is actually performed; later agents *might* retrieve it. Assumptions: the agent can find/use the retained material, governance remains valid.
- `PATH-2`, **bounded product-core bootstrap, then accrete**: a more front-loaded breadth approach with possible wider initial coverage but additional up-front work/maintenance and risk of modeling unused possibilities. Its value is not logically identical to PATH-1, and the source compares them at the same strategic path level.
- **No independent third path** was ratified because another initially floated option did not survive the source comparison. The source does not impose an arbitrary minimum count.

**Rationale A-R1:** given accepted ADR 0031 and the current narrow source context, the A author judges PATH-1 more reversible and immediately connected to genuinely valuable engineering work than PATH-2; some of PATH-2's orientation value was already supplied by auto-loaded context. The original report's `BUILD` / selected PATH-1 / proposed `PATH-1/T1` are **a Level-3 candidate direction**, not an issued permission to modify a component. It explicitly says implementation/PR/merge/release authority did not follow from the read-only strategic request.

**Reconsideration A-H1:** later independent sessions might fail to discover or apply reviewed knowledge; other work might never cover valuable products outside the plane. Both could change the comparison or call for tighter bounded work; their possibility alone does not invalidate the direction.

**Strategic distinctions exercised:** accepted end vs knowledge mechanism, strategy vs work, future hypothesis vs observation, alternative paths vs optional components, omission cost vs overconstruction, choice vs authority, no fabricated new product end. **Negative A-N1:** treating every additional repository graph edge as a product future would compare the wrong thing.

**SEL coverage:** 01–10, 18, 20.

## 3. B — Learning updates an assumption while preserving the direction

**Exact predecessor:** case A at `aa13f40`, with `PATH-1` over `PATH-2` and `ASSUMPTION-1` and `ASSUMPTION-2`. **New assessed state:** `b5fc389` as attributed by the 2026-10-24 author.

**World/source change B-W1:** the report observes that PR #565 has added source-backed product-contract knowledge outside the earlier knowledge plane; the old `FRONTIER-1` absolute statement about *no* such modeling is now too strong. The report also observes the legacy producer remains unchanged and a prior violation remains open. These are **source observations**, not an empirical later-agent creative-outcome measure.

**Understanding correction B-U1:** original `ASSUMPTION-1` stated that later independent sessions would query relevant reviewed knowledge. New reachability evidence makes that depend on actual host discovery or an always-loaded pointer, neither then established in target repositories. The appropriate disposition is `REVISE` (narrow/prerequisite), not `INVALIDATE` or "knowledge never helps."

**Confirmed premise B-C1:** `ASSUMPTION-2`, that auto-loaded instructions preserve relevant core contracts, is `CONFIRM`ed with cited source; it is not a new feature added on 2026-10-24.

**Exact strategic result B-R1:** `CONTINUE PATH-1`; `PATH-1/T1 PARTIAL` because source modeling happened before the expected engineering change; `REAFFIRM` strategically. One changed premise and several source updates do **not** imply a new Strategic Frontier, changed beneficiary or Level-4 product-thesis choice. A, its alternatives and original source identity remain intact.

**What is not established B-N1:** no later independent agent reused the new path knowledge beneficially; a source record becoming reachable does not prove improved user judgment. Changing the interpretation of an assumption is not proof that the repo's underlying code changed *in the same respect*. Later work should distinguish an actual software patch from this attributed reconciliation.

**Learning-account sketch B-L1:** prior target `ASSUMPTION-1` / author/source A; new source B; reason reachability prerequisite; `UNDERSTANDING_CHANGED` (and related source-state change to modeled knowledge); revised target `REVISE`; unaffected `ASSUMPTION-2 CONFIRM`; overall `REAFFIRM`; owner/product thesis unchanged; revisit with genuine independent use.

## 4. C — Learning across related episodes does not establish transferable doctrine

**Source:** case C; baseline is `b497ad7`. **Question:** can a later file-first engineering inquiry recover meaningful historical context when relevant sources exist but an authored graph link is missing?

**Observed source-linked cases:**
- **#691:** a specific comparison guidance path lacked owner/decision anchors. **#696** later gave a positive exact-head `context-for` result for *reviewed paths*, serving as a **counterexample** to the general claim that file-first retrieval is universally broken.
- **#697:** prospective Steward source guidance lacked exact `component.owned_paths` despite other component/decision information; a bounded path ownership correction was made.
- **#701:** a newly authored creative reference also lacked the exact owner path; the source-pinned component link was added without inventing a new query algorithm.
- **#704:** a history consumer needed explicit owner-to-existing-lesson `references` links, distinct from merely adding a file ownership path.

**Candidate lesson C-L1:** when a consequence-bearing `context-for` query lacks relevant history, first inspect exact owning component paths, allowed explicit relations and original cited sources; prefer a minimal reviewed source/graph correction *if* that is the demonstrated defect. Do not assume either "the query engine is wrong" or "more knowledge must exist" from a single `NOT_ASSESSED` answer.

**Counterevidence C-X1:** common symptoms arise from **different mechanisms** (missing owner identity vs missing exact owned path vs absent history link). The report discusses the **same repository and related consumers**. That overlap is not multiple independent cross-repository causal corroborations. Adding unreviewed links can produce stale/noisy results. Source-only reconstruction may be cheaper than a persistent index.

**Qualified outcomes:** relevant PR and hosted consumer checks support **mechanical source reachability** at particular versions. The report does not observe an independent later agent retrieving, source-checking and materially using this lesson, let alone a comparative improvement in its decision. A safe later outcome could be **reject this lesson** when the target's retrieval engine is an exhaustive scan or has materially different ownership semantics.

**Learning scope C-S1:** repository-local repeated pattern and conditional reusable *question*, **not** a promoted universal `CapabilityLearning` doctrine or Skill mutation. Context limits, contrary examples and original source revisions stay visible.

**Negative C-N1:** "Four PRs encountered a retrieval omission, therefore all agents need a new MemoryEngine" confuses repeated observations with one common cause, and a local troubleshooting response with a universal new product commitment.

**SEL coverage:** 03, 06, 09, 11–16, 18–20.

## 7. F — Normative three-way separation: world, interpretation and governing intent

**Not historical.** This illustration demonstrates an intended distinction, not three recorded code or owner events.

| Hypothetical event | Actual change type | Evidence needed | Likely consequence that does **not** follow automatically |
| --- | --- | --- | --- |
| A documented function is modified and source-/behavior-verified at commit R. | **WORLD_CHANGED**; understanding may additionally need updating. | Before/after source and appropriate evidence, exact target version. | No evidence that product goals, later user benefit or strategic PATH changed solely from code change. |
| An agent discovers the function already existed in the original source but previous report missed it. | **UNDERSTANDING_CHANGED**; actual old source may be unchanged. | Original pre-discovery file/revision and prior source-attributed claim. | Do not credit a new implementation or infer a changed Level-4 purpose. |
| The owner *explicitly* ratifies a different primary beneficiary/problem. | **GOVERNING_INTENT_CHANGED**, with its source/decision author. | Actual owner/ADR or equivalent documented decision and affected dependent work. | Do not represent this as the agent empirically discovering a better product or automatically authorize unrelated implementation. |

Two or more changes can coexist in real life. This conceptual lens must not overwrite canonical epistemic or policy enums. It identifies the **object of change**, not proof of its truth or extent.

**Negative F-N1:** a file changed, therefore strategic doctrine invalidated. **F-N2:** an agent found an old ability, therefore a new user feature was built. **F-N3:** a novel desirable hypothesis emerged, therefore the owner has selected a new thesis.

**SEL coverage:** 11–14, 17–20.

## 8. Cross-case counterfactuals and qualification ceiling

| Potentially misleading conclusion | Reconstructible correction |
| --- | --- |
| A strategic frontier is a list of absent features or tickets | A: named governing outcome and credible future-capability consequence are required; bounded repairs can be valuable without Level-3 elevation. |
| A new technical mechanism is necessarily a new valuable product end | A/E: mechanism and documentation may serve accepted ends; genuinely new beneficiary outcomes need independent hypothesis/value checks. |
| The best-looking new direction must be built | A/D: provisional analysis, comparison purpose and implementation/owner authority are distinct. |
| Future benefit is proven from a multi-hop inferred consequence | A/C/E: separate source present-state claim, hypothetical mechanism, observed beneficiary benefit and unknowns. |
| New source or drift invalidates current strategy | B/E: interpretations and precise assumptions can change while `PATH-1` and owner thesis remain intact. |
| Learning requires a revised rank, a new persistent file or a new Skill | B/D/E: `REVISE` one assumption, `REAFFIRM` whole path, `NO_MODEL_CHANGE` or appropriately scoped `NO_CHANGE` are all complete outcomes. |
| Historical events should be overwritten to keep "current" memory | B/C: preserve old source identity; revise the present interpretation and record its applicability. |
| A historical lesson retrieved by a later agent is automatically binding | C: a different architecture/consumer may make the analogy inapplicable. |
| Several related PRs establish cross-repository doctrine | C: no independent different-repository comparison, and distinct causes/counterexample remain. |
| A hosted CI check proves later-agent reasoning benefit | E: exact-source mechanical checks and later-agent semantic use are distinct evidence classes. |
| An owner change can be deduced from repository code | F: owner intent requires an actual owner/authority source; hypothesis alone cannot ratify Level-4. |
| Missing graph edge proves product absence | A/C: `NOT_ASSESSED` and source-only fallbacks remain; no negative existential inference. |

**What these cases establish:** a source-literate reader can recover specific past authors' documented strategy/learning interpretations and identify their limits, historical alternatives, nonchanges and authority. **What they do not establish:** fresh agents using the new two-profile ontology, improved cross-session creativity, measurable better strategic paths, independent cross-repository transfer, automatic strategic changes or approved new ProductPossibilities.
