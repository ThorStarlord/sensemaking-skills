# Adaptive Metareasoning System (AMS) — Development and Implementation Program

**Date:** 2026-11-12
**Status:** owner-selected product end, conditional engineering implementation program; not a fixed backlog or behavioral-success claim.
**Architecture:** single using-sensemaking agent-native controller, existing semantic policies, source-retrieval and learning/reconciliation.
**Design:** [AMS product design v0](../specs/2026-11-12-adaptive-metareasoning-system-design.md).
**Product authority:** [ADR 0036](../../adr/0036-adaptive-metareasoning-system.md), ADRs 0029/0031/0034/0035, [product strategy](../../product-strategy.md), and [Level-4 revision contract](../../product-thesis-revision.md).
**Planning baseline:** ThorStarlord/sensemaking-skills main c644323abab5f9ca7808f1f2369b2ccb22286828. Refresh at every implementation responsibility.

## Program rule

Proceed autonomously with independently warranted, authorized repository work. Each stage must ground its actual consumer, evidence, authority and retained value; later stages are conditional on results, not automatically executable merely because they appear in this document. A genuine NO_CHANGE/STOP is valid. Use the existing local construction policy in CLAUDE.md, including the current prohibition on adding or manually running local unit/synthetic evidence tests; report NOT_RUN honestly while preserving hosted CI and mandatory protections.

Differentiate:
- conceptual representation from guidance delivery;
- guidance availability from use by a later actor;
- use from benefit;
- product outcome from method effectiveness;
- explanatory record from original timestamped host evidence;
- current decision authority from foreign-repository lessons.

Do not create a second controller, another Skill package, automatic cognitive router, schema or method-progress score to make AMS appear implemented.

## AMS-P2 — Question-fitness and misleading-progress behavior

**Source owners:** cognitive-orientation-crosswalk-v1.md, prospective-reasoning-ontology.md, metareasoning-policy-v0.md, and Stage 3 A/D and Stage 4 records.

- [ ] Identify a real source-grounded question whose governing purpose is consequential.
- [ ] Reconstruct original frame, method, evidence and what the output answered.
- [ ] Distinguish corrective reframing, productive question evolution, and unrelated curiosity.
- [ ] Verify source-to-question transformation and whether the original answer remains valid.
- [ ] Prefer smallest correction to an existing consumer/reference only if the deficiency changes a decision.
- [ ] Prevent silent owner-goal replacement, scope expansion and duplicate ontology types.
- [ ] Qualify only what observable work shows, including valid narrow/STOP counterexamples.

**Gate:** an authentic decision-relevant comparison exists. Conceptual examples alone do not open an automatic PR.

## AMS-P3 — Diagnose inadequate method and correct proportionately

**Source owners:** existing Metareasoning/Exploration/Inquiry Policy, abductive guidance, execution/harness authority and bounded source evidence.

- [ ] Start from an actual inadequate result or repeated friction.
- [ ] If consequential, distinguish source error, flawed inference, bad question, method unsuitability, method misexecution/composition, host availability and authority blockage.
- [ ] Identify the smallest observation that would discriminate among plausible causes.
- [ ] Prefer correcting evidence/one inference/one lens before restarting an entire inquiry.
- [ ] Verify selected correction against the actual failed behavior, not just the new document.
- [ ] Keep valid findings and method stability when appropriate.

**Gate:** real inadequacy, not an invented failure scenario.

## AMS-P4 — SCL-informed adaptive judgment

**Source owners:** ADR 0035, SCL program and Repository Semantic Steward RECALL, existing lesson/learned_from records, exact-revision query modes.

- [ ] Identify a later decision where a historical methodological lesson could change action.
- [ ] Retrieve from the current question/file, not by choosing a favored historical lesson beforehand.
- [ ] Check original source revision, currentness, counterevidence and applicability.
- [ ] Observe actual use, adaptation or reasoned rejection before the consequential choice when the host makes chronology accessible.
- [ ] Preserve current repository authority; no automatic learned method preference.
- [ ] Reconcile feedback via existing SCL surfaces; do not duplicate lesson extractors or SCL-owned PRs.

**Gate:** an authentic later-agent consumer and honest encounter timing. Retrieval alone is not completion.

## AMS-P5 — Observability and evidence proportionality

- [ ] Reuse original task, Git/PR source, session/query receipts, available host/tool events and Decision Observability v1.
- [ ] Distinguish declared contemporary rationale, observed action and retrospective interpretation.
- [ ] Preserve enough timestamped context for a consequential decision, without private reasoning or secrets.
- [ ] Add optional mechanical evidence projection only if repeated source-based consumer need is established.
- [ ] Record unavailable original trace as NOT_ASSESSED; do not reconstruct by simulating the old run.

**Gate:** observed missing evidence changes an actual adoption or repair decision.

## AMS-P6 — Authentic qualification

**Target conditions:** actual bounded engineering tasks with clear purpose, misleading-progress risk, ambiguous failure causes, correct-answer-new-question opening, temptation to expand scope, historical lesson context or protected authority.

- [ ] Select cases for real product value; avoid selecting tasks for easy AMS positivity.
- [ ] Verify task, agent/host and installed Skill identity; retain original accessible events where possible.
- [ ] Examine useful action and relevant direct/direct-stop controls; include negative cases.
- [ ] Compare with a credible alternative only if making a causal/comparative adoption claim.
- [ ] Assess false-positive reframing, delay, rework, tool/reading cost, and authority adherence.
- [ ] State A/B/C/D evidence ceiling, counterexamples, confidence limits and keep/revise/retire conclusion.

**Gate:** behavior and product value, not just tests, CI or a polished narrative.

## AMS-P7+ — Conditional executable support

Candidate future seams: bounded retrieval of methodological context, source-currentness disclosure, optional observable-decision projection or question-lineage presentation. None is pre-authorized for construction.

For any candidate require: named consumer, observed consequence, proof existing tool/guidance cannot serve it, bounded input/output contract, compatibility, acceptable maintenance and failure modes, source/diff checks and appropriate authority.

Reject by default: central MetareasoningEngine, deterministic cognitive scoring/routing, mandatory reflection hooks, general new agent/belief state, self-modifying policies, automatic question-goal changes, foreign repo control, routine transcript recording.

## PR and operating boundaries

Suggested PR boundary: a product-identity + discoverable-first-use slice may be one coherent PR if the diff remains narrowly reviewable. Subsequent PRs should follow independent genuine product defects or valuable responsibilities; do not open PRs solely to check milestone boxes.

Current CLAUDE.md controls branch naming, PR source/diff review, NOT_RUN local unit/synthetic tests, hosted CI and merge authorization. Integration is not evidence of independent method selection or product benefit.

## STOP / REVISIT / RECONCILE

- **ACT/BUILD:** a useful, bounded, already authorized improvement has sufficient warrant.
- **INQUIRE:** a particular unresolved source/behavioral fact would alter a consequential decision.
- **VERIFY/QUALIFY:** the claim depends on evidence current work can proportionately obtain.
- **STOP/NO_CHANGE:** existing support suffices or no genuine task/consumer is available; do not rebrand unfinished research as work.
- **REVISE/REJECT:** evidence reveals cognitive false positives, authority failures, noisy lessons or excess process costs.
- **OWNER/EXTERNAL:** only genuinely reserved authority/host blockers stop that protected action; other independent work may proceed.

**Definition of success:** users and agents can exercise AMS through the current single Skill, and genuine engineering behavior progressively justifies stronger claims that its purpose/effort/question regulation improves decisions economically. A selected product end is not a proven outcome.
