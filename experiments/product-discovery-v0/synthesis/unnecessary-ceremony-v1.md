# Unnecessary ceremony v1

## Steps that felt ceremonial

- Repeating the full ten-heading loop in every case created prose duplication after the decision, uncertainty, probe, and synthesis were clear.
- Fine-grained lifecycle classification did not change the probe when a case spanned problem validation and solution validation.
- Separate “original hypothesis,” “what changed,” and “disposition” fields often restated the same update.
- Kill criteria were weak for repository-only inspection; they become valuable when a probe can consume repeated time, money, or implementation effort.
- Formal success thresholds would have been invented because the repository supplies no justified base rates.

## Combine the method

A future manual worksheet can use six blocks:

1. **Decision and materially different alternatives** (including do nothing).
2. **Observed evidence vs interpretations.**
3. **Decision-changing uncertainty and reality boundary.**
4. **Cheapest credible probe.**
5. **Precommitment:** observations, disconfirming evidence, stop condition, ambiguity.
6. **Update:** what changed, confidence, disposition, next probe.

Use uncertainty type as an optional tag, not a required taxonomy exercise. Use explicit kill criteria only for repeated/costly/consequential probes. Do not automate prose generation: verbose completeness can disguise absent evidence.
