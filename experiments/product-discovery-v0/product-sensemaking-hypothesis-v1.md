# Product-sensemaking hypothesis v1

> Product hypothesis: Sensemaking Skills should evolve from a software-engineering workflow router into a system that determines what kind of thinking and work should happen next.

## FOR

- The five cases show that the next useful action is often learning, comparison, consent clarification, or a user-choice observation—not construction.
- Existing repository history itself warns against overreach: externally proven capability is narrower than routing/orchestration positioning.
- Explicit evidence boundaries can prevent engineering artifacts from being mistaken for product validation.
- The reasoning could complement repo-sensemaker's “diagnose, do not implement” boundary without deciding product direction.

## AGAINST

- No external user has demonstrated demand for a meta-layer.
- A system that selects “what thinking happens next” risks becoming a universal router with vague authority and hard-to-validate outputs.
- The useful steps fit on one page; packaging them as a skill may add ceremony, taxonomies, schemas, and governance before value.
- The repository has more direct unfinished validation: substantive external brief usefulness, routing accuracy, executor coverage, and repeatability.
- Product decisions contain values and real-world evidence that an agent cannot autonomously resolve.

## EVIDENCE MISSING

- Prospective before/after decisions showing the manual loop changes an owner's action.
- Evidence that changed actions improve outcomes or reduce wasted implementation.
- Frequency and cost of these decisions.
- Whether maintainers prefer the loop over ordinary conversation.
- Whether a narrow checklist works across product, governance, execution, and routing cases without expert facilitation.

## CHEAPEST NEXT TEST

For five real owner decisions, record the intended action before facilitation; run the six-block manual worksheet; record action after, reason for change, time cost, external evidence requested, and later whether that evidence affected the decision. Use no new skill, schema, router, or runtime. Have the owner judge whether the interaction was useful. Stop if it only reformats decisions without changing evidence sought or action.

## Current evaluation

**KEEP AS AN UNVALIDATED PRODUCT HYPOTHESIS.** The experiment supports the usefulness of a manual upstream questioning practice. It does not support evolving the repository's settled product definition or building a `product-sensemaker`.
