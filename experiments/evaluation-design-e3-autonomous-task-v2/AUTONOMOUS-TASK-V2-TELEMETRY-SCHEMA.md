# Autonomous Task v2 — Telemetry Schema

Status: DRAFT. Field names below are proposed and machine-readable-oriented;
they are not yet declared in any artifact-contract file and carry no binding
force outside this experiment.

## Run identity / provenance

```
run_id                  string, unique per (task_instance_id, regime, attempt)
task_instance_id        string, e.g. "T1-MEDIUM-01"
task_family             enum: T1 | T2 | T3
complexity_level        enum: MEDIUM | HIGH
regime                  enum: R0 | R1 | R2
regime_prompt_hash      sha256 of the exact regime text delivered
task_bundle_hash         sha256 of the exact task-visible contract delivered
base_sha                 the frozen repository commit this run's clone was cut from
clone_path                path/identifier of the standalone clone used
agent_session_id         opaque session identifier (never reused across runs)
run_order_index           this run's position in the randomized dispatch
                          order, generated by a frozen seeded Fisher-Yates
                          shuffle (AUTONOMOUS-TASK-V2-PROTOCOL-DRAFT.md §3b)
                          logged before dispatch, not chosen ad hoc
run_started_at / run_ended_at   ISO-8601 timestamps
```

## Agent resource cost (raw, retained independent of any price conversion)

```
input_tokens_total
input_tokens_task_bundle      constant per task, logged for the robustness check
input_tokens_regime_prompt    logged separately per Design Options §2 Option A
output_tokens_total
model_turns_count
tool_calls_count
tool_calls_by_type            map: tool_name -> count
subprocess_executions_count
subprocess_runtime_seconds_total
failed_commands_count
retries_count
wall_clock_seconds_total
monetary_cost_usd             RETIRED as an independent field -- aliased
                               exactly to operational_actual_cost_usd
                               (defined below) so the two names can never
                               drift apart. Any code/report still emitting
                               monetary_cost_usd must read it from
                               operational_actual_cost_usd, never compute
                               it separately from turn/token counts using a
                               different formula.
```

**Per-model-call telemetry, corrected twice** — Lock-Readiness Response 2
§4 first replaced a flawed single-subtraction formula with per-call
accounting because static context (task bundle + regime prompt) is
typically present on every call, not billed once; Lock-Readiness Response 3
§7 then found per-call subtraction is still unsafe as a *dollar* figure,
since a provider's `cached_input_tokens` can conflate genuine conversation
history with the static prefix — demoted accordingly:

```
model_calls[]                    one entry per model call in the run:
  call_index
  input_tokens
  cached_input_tokens            if the provider reports cached-token counts
                                  distinctly; null otherwise. NOTE: this
                                  figure can include cached CONVERSATION
                                  HISTORY, not only the static task/regime
                                  prefix -- do not assume it is safe to
                                  treat as "static prefix" without provider-
                                  specific cache-segment attribution.
  output_tokens
  model_id
```

**One primary confirmatory dollar measure, plus required token-level
diagnostics — not two dollar views:**

```
operational_actual_cost_usd      sum of what was genuinely billed across
                                  every call in model_calls[] (cached-token
                                  pricing applied where the provider reports
                                  and prices it distinctly) — "what would
                                  deploying this regime actually cost." THE
                                  sole primary, confirmatory dollar measure.
dynamic_execution_input_tokens   for each call: (input_tokens -
dynamic_execution_output_tokens  static_prefix_tokens), floored at 0,
                                  summed across all calls, where
                                  static_prefix_tokens = input_tokens_
                                  task_bundle + input_tokens_regime_prompt
                                  (the RAW static prefix, never substituted
                                  with a provider's whole cached-token
                                  count). TOKEN counts, not dollars --
                                  required, co-equal DIAGNOSTIC reporting
                                  used to interpret why a cost difference
                                  occurred, never a confirmatory dollar
                                  claim on their own.
dynamic_execution_resource_cost_usd (OPTIONAL, best-effort/conditional)
                                  a dollar figure derived from the above,
                                  computed ONLY when the provider exposes
                                  exact cache-segment attribution
                                  (distinguishing "static prefix" from
                                  "prior turns" within its cached-token
                                  report). Never promoted to confirmatory
                                  status alongside operational_actual_cost_usd
                                  even when present.
```

(`execution_phase_cost_usd`, the original single-subtraction field, is
retired — its intent is now split across the token-diagnostic fields above
and the conditional dollar field.)

`operational_actual_cost_usd` and the two `dynamic_execution_*_tokens`
fields are computed and reported for every run; neither the dollar measure
nor the token diagnostics is optional. **Human supervision minutes are
never converted into any cost field** — see "Human attention cost" below
and the sensitivity-analysis field in "Derived economic fields."

## Human attention cost (kept separate from research/evaluator labor)

```
human_active_seconds_total             DEFINED, not merely reported, as the
                                        sum of every per-category duration
                                        below that represents genuine human
                                        active time on THIS run:
                                        human_active_seconds (escalation,
                                        R2 only) + operational_recovery_
                                        seconds + approval_review_seconds.
                                        manual_repair_seconds and
                                        research_evaluator_labor_seconds are
                                        explicitly EXCLUDED from this total
                                        -- the former because it is
                                        post-acceptance salvage cost (see
                                        below), the latter because it is
                                        research/evaluator labor, not
                                        operational human attention (both
                                        already excluded from the
                                        operational human-attention total
                                        per their own field descriptions).
escalation_count                       (R2 only; must be 0 or 1)
escalation_request_emitted_at          ISO-8601 -- when the agent sent the
                                        escalation request (R2 only)
responder_started_at                   ISO-8601 -- when the responder
                                        actually began working the request,
                                        NOT when it arrived (R2 only)
responder_submitted_at                 ISO-8601 -- when the response was
                                        sent (R2 only)
human_active_seconds = responder_submitted_at - responder_started_at
                                        (added in Lock-Readiness Response 3
                                        §8 -- NEVER computed as
                                        responder_submitted_at -
                                        escalation_request_emitted_at, which
                                        would be latency, not attention).
                                        If responder_started_at cannot be
                                        captured in a given execution
                                        environment, this field is renamed
                                        response_latency_seconds for that
                                        run and no human-attention-savings
                                        claim may be drawn from it.
escalation_request_text                verbatim, logged
escalation_response_text                verbatim, logged
responder_blinded                      boolean, R2 only — true iff the
                                        escalation responder received only
                                        the visible task contract, permitted
                                        environment facts, and the agent's
                                        request (never the hidden oracle or
                                        intended solution route); if false,
                                        the run's evidentiary weight for H3
                                        is explicitly limited, not silently
                                        counted as equivalent (added — was
                                        required by
                                        AUTONOMOUS-TASK-V2-EVALUATOR-SCORECARD.md
                                        §4c but missing from this schema)
operational_recovery_seconds           time spent by a human fixing agent errors,
                                        if any — 0 for a clean run
approval_review_seconds                time a deployment-realistic approval step
                                        would cost, if applicable to the task
manual_repair_seconds                  time spent by a human attempting to
                                        salvage a run AFTER its accepted
                                        value is already frozen (see below)
salvaged_after_manual_repair           boolean -- true iff a human repair
                                        attempt followed a NOT_ACCEPTED
                                        outcome. Added in Lock-Readiness
                                        Response 3 §9 to close a real risk:
                                        manual_repair_seconds' prior
                                        description implied repair could
                                        occur BEFORE and be conditioned on
                                        reaching ACCEPTED, entangling
                                        efficacy and cost-benefit. Neither
                                        this field nor manual_repair_seconds
                                        can ever change an already-frozen
                                        accepted value (protocol §6) -- a
                                        NOT_ACCEPTED run that is later
                                        salvaged remains NOT_ACCEPTED for
                                        efficacy/economics purposes; the
                                        salvage cost is recorded separately,
                                        for deployment-realism discussion
                                        only.
research_evaluator_labor_seconds       explicitly SEPARATE field — adjudication/
                                        analysis time, never summed into the
                                        operational human-attention total
```

## Waste telemetry (evaluator-interpreted, with explicit definitions)

```
duplicate_reads_count            same file/command re-read with unchanged state
redundant_validations_count      validation run with no plausible new failure
                                  mode since the prior identical validation
abandoned_routes_count           an investigated route later not used
repeated_searches_count          semantically equivalent search issued 2+ times
unnecessary_file_inspections_count   file opened with no resulting action or
                                      decision traceable to it
work_later_discarded_count       edits made then reverted/replaced by the same run
background_stall_seconds         time lost to avoidable wait/poll loops
route_evidence_trace             list of tool-call indices where the agent
                                  actually inspected consumer-side evidence
                                  (not just the artifact it ultimately
                                  edited) supporting its chosen route —
                                  added in Hardening Pass 1 to close the
                                  "obviously intended route" convergence
                                  gap; see
                                  AUTONOMOUS-TASK-V2-HARDENING-PASS-1.md §6
                                  Risk C; applies primarily to T1
```

Each waste field requires the evaluator to cite the specific tool-call
indices supporting the count in the scorecard (see
`AUTONOMOUS-TASK-V2-EVALUATOR-SCORECARD.md`) — a bare number without cited
evidence is not accepted as adjudicated telemetry.

## Outcome / acceptance fields

```
goal_state                 ACHIEVED | NOT_ACHIEVED
process_contract            SATISFIED | VIOLATED | NOT_APPLICABLE
instrument_validity          VALID | ORACLE_INVALID | BASELINE_CONTAMINATED
                              | ISOLATION_BREACH | HARNESS_UNSTABLE
escalation_classification    NONE | LEGITIMATE_ESCALATION | ESCALATION_LAUNDERING
accepted                     boolean, derived per protocol §6 acceptance rule
accepted_with_escalation     boolean, R2 only
failure_modes_tagged         list of enum values from the preregistered set
                              (protocol draft §11), may be empty
```

## Interruption classification

Any run that experiences a stall, tool failure, or forced background
execution must classify the interruption as exactly one of:

```
AGENT_OPERATIONAL_COST     would recur in real deployment (e.g. a genuinely
                            slow but working command) — stays in cost totals
INSTRUMENT_HARNESS_INVALID  a benchmark-infrastructure artifact (e.g. sandbox
                             timeout unrelated to the task) — excluded from
                             cost totals, run flagged HARNESS_UNSTABLE
```

This classification must be made at the time of the interruption, with a
one-line justification, not reconstructed after seeing the run's final
outcome (to avoid post-hoc rationalization toward whichever classification
makes a preferred regime look better).

## Cross-run leakage audit

```
prior_run_visible            boolean — did this run's session have any
                              access to artifacts/output from another run of
                              the same task_instance_id?
shared_clone_detected         boolean — did this run share a clone/worktree
                               path with any other run?
leakage_finding                free text, required if either boolean is true
```

## Derived economic fields (computed post-hoc, not logged per-run)

```
cost_per_accepted_task_usd              (aggregate; failures in numerator)
cost_per_accepted_task_wallclock_seconds
cost_per_accepted_task_human_minutes
paired_delta_vs_R0                      per task_instance_id, per regime;
                                         primary dollar delta on
                                         operational_actual_cost_usd, plus
                                         required token-diagnostic deltas on
                                         dynamic_execution_input_tokens /
                                         dynamic_execution_output_tokens
                                         (Lock-Readiness Response 3 §7)
paired_cost_delta_matched_outcomes      task-by-task ROBUST-vs-LEAN cost
                                         comparison restricted to pairs where
                                         BOTH runs were ACCEPTED — kept
                                         co-equal with the aggregate metric
                                         above, never replacing it (Lock-
                                         Readiness Response, non-blocker
                                         item 2)
break_even_rate_usd_per_hour            only if a human baseline exists (r*)
total_cost_at_rate[]                    sensitivity-analysis ONLY, never a
                                         primary metric and never feeding
                                         H1-H5 or the Tranche-2 rule: array
                                         of {rate_usd_per_human_hour,
                                         total_cost_usd} at a small
                                         preregistered set of rate points
                                         (e.g. $0/$50/$150/$400/hour) —
                                         the only place human minutes are
                                         ever combined with dollar cost
                                         (Lock-Readiness Response 2 §5)
```
