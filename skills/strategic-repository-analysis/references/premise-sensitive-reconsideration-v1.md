# Premise-Sensitive Reconsideration v1 — Optional Agent-Native Inquiry

**Role:** source-grounded reasoning procedure for a consequential changed-premise, comparison, learning, or prospective question. This is **not** an additional public Skill, deterministic graph planner, automatic strategic reopening, registered artifact, new graph schema or browser requirement. The active `using-sensemaking` agent owns whether inquiry is warranted, the answer, and the authority boundary.

**Portable:** No index, local `.sensemaking` directory, fixed ADR naming, browser, or Sensemaking CLI is required for a target repo. Source-only is a legitimate successful implementation.

## When to use and skip

Activate for questions such as “Which rejected ideas may be worth revisiting if P changed?”, “Would the prior preference still hold under constraint C?”, “What did we learn that narrows a preceding decision?” or “What new user outcome might these previously independent capabilities support together?”

Skip for a routine code edit with adequate current sources, or when there is no consequential prior judgment or premise to inspect. Never make a mandatory graph discovery stage. Honor the source/owner scope; an inquiry question is not an implementation order.

## Inquiry, not choreography

1. **Identify the real question:** beneficiary/end, historical target and decision frame, which premise may have changed, present target repository/Git revision, original source-assessed revision, and applicable authority. A historical `PATH-1` is scoped to its dated strategic analysis, not an automatically global graph node.
2. **Selective recovery:** inspect original ADRs, strategy, analysis, decision/reconciliation, source and evidence. If an exact-revision index exists, use existing `knowledge-query` `search`, `explain`, `why`, `history`, `changes`, `context-for` and `contradictions` to find *candidate* relationships, then inspect original sources. If no index or a sparse neighborhood, use direct source reading; a missed link does **not** establish absence.
3. **Establish relationship roles:** for each claim/judgment specifically, classify a source-supported association as `NECESSARY`, `SUPPORTING`, `DEFEATER`, `CONTEXT_ONLY` or `UNKNOWN`. `SCENARIO_ONLY` is for a user/agent counterfactual. A bare `references` or proximity edge can only suggest where to inspect; it cannot establish necessity, rejection or causation. For several premises say `ALL`, `ANY` or `UNKNOWN` only when the sources warrant the distinction.
4. **What changed and what did not?** Separate source/world changes, interpretation changes and actually changed owner/governing intent. A source file hash or graph edge does not by itself reopen Level 3/4. Name unaffected alternatives and the reasons the old conclusion might still hold.
5. **Challenge decisive bridges:** Is the alleged premise essential or merely supportive? What source or counterexample contradicts the inference? Are comparisons made for the same beneficiary/frame? Would a later target host have been able to retrieve the original lesson? Distinguish historical author's decision from a new agent recommendation.
6. **Explore only when useful:** assumption inversion, temporal revival, complementary capability synthesis, contradiction challenge or negative-space search may suggest a new future. Compare it with the closest sourced `poss:` and `arch:`. `RESTATED` / `REVISED` / `NEW` / `NOT_ASSESSED` require semantic differentiation; a new mechanism is not automatically a new desired user outcome.
7. **Produce an accountable answer:** what the record established, what the agent inferred, what remains hypothetical, what remains unknown or truncated, which earlier judgment merits closer inspection, and what stays valid. A result can be `NO_MODEL_CHANGE` / `CONTINUE` or an unresolved question. A provisional preference is neither selection nor action authorization.
8. **Optional visual companion:** if a dense set of alternatives/assumptions needs inspection, use an explicitly bounded source-pinned `knowledge-view-export` when available; its browser view is secondary and read-only. Selecting a scenario produces a copy-ready new prompt for the primary agent. The browser never edits reviewed knowledge or issues protected commands.
9. **Selectively retain:** only if future agents materially benefit, reconcile a source-checked lesson/possibility/revised premise through existing Steward review. `NO_MODEL_CHANGE` is valid. Never persist every inference as a new ontology row.

## Concise response shape

> **Question and historical target:** What does the user want to decide/understand, for whom? Original authored target ID, source, scope and assessed SHA.  
> **Current source:** What has actually changed and at which examined Git revision? Is that different from the index SHA?  
> **Premise roles:** What was `NECESSARY` / `SUPPORTING` / `DEFEATER` / `CONTEXT_ONLY` / `UNKNOWN`, with checked sources and any contrary evidence?  
> **Reconsideration:** Which *particular* interpretation/comparison warrants revision; which alternatives and governing choices remain unchanged?  
> **Prospective insight:** Novel end versus old end/new mechanism; nearest prior `poss:`/alternative and uncertainty.  
> **Evidence limits / authority / stop:** What was retrieved versus inferred, what is missing, and whether the next step is source inquiry, no change, a separately authorized choice, or owner decision.  
> **Optional viewer:** Link to a local read-only selected neighborhood and copy-back scenario, never source of authority.

## Reference case and negative controls

The 2026-10-23 strategic analysis at `aa13f40` recorded `PATH-1` and `ASSUMPTION-1` (“later separate sessions query reviewed knowledge”). The 2026-10-24 reconciliation at `b5fc389` **REVISE**d that assumption for the missing reachability prerequisite, **CONFIRM**ed `ASSUMPTION-2`, and **CONTINUE**d/`REAFFIRM`ed PATH-1. It did not negate prior owner intent, prove reuse impossible or authorize a new strategy. Original sources are in `artifacts/history/`; documentary crosswalk in `docs/semantic-architecture/strategic-evolution-learning-reference-cases-v1.md`. The target repository may not have those Sensemaking paths; when absent, substitute its real historical sources.

Negative controls:
- A co-cited or adjacent link is **not** a premise supporting or defeating a claim.
- A premise becoming uncertain does **not** automatically invalidate every supported conclusion.
- A changed indexed file is **not** a new owner goal.
- A graph miss is **not** negative evidence; source-only analysis may answer.
- A copied prior idea is **not** a new ProductPossibility.
- A human changing a hypothetical browser scenario is **not** a ratified source or permission to execute.

## Evidence ceiling

Separate source retrieval, source-checking, material use in the agent's interpretation, a genuinely new benefit, independent later-session reuse, and comparative advantage over a similarly equipped source-only agent. A skill reference, curated example, CLI graph view, hosted CI or same-session application does **not** establish the latter two.
