# Convergent Evaluation and Scoped Direction Selection v1

**Load when:** a live, warranted question asks which of several materially credible directions to adopt, or whether a provisional choice is justified for the declared purpose. This portable guide serves the existing `strategic-repository-analysis` and `using-sensemaking` Skills. A standalone source comparison, existing authorized repair or mere divergent exploration does not automatically invoke it.

**Result:** an attributable **source-grounded recommendation**, an actual **scoped selection made within valid authority**, or a clearly reasoned **nonselection/handoff**. It is not a new public Skill, ranking engine, mandatory workflow, decision authorization or implementation trigger.

## 1. Name the choice before evaluating options

Identify the actual user goal, bounded decision question, current canonical source revision, product/engineering authority and intended commitment. Name its **typed target**. Examples:

- `InquiryQuestion + ProposedInquiryApproach`: select a *next investigation* and its method, not the future product identity.
- `ProductPossibility` or coherent product direction: compare a future state and consequences; the authority to adopt a product-thesis change may remain reserved.
- `ArchitectureOption / ConstructionPath`: use existing Level-3 synthesis/selection contracts and scope.
- Independently authorized bounded change: evaluate its actual prerequisites and side effects; no ontology record creates the authorization.

When the user requests only a comparison or next intellectual exploration, do **not** silently enlarge scope into product ratification or code. A positive direction answer can remain a recommendation without becoming a `Decision`.

## 2. Check option-set adequacy

Inspect the available original candidates and their evidence, retained `poss:` identities, prior comparison frames, and any plausible status quo or smaller/no-change direction. Ask whether a consequential upstream path, beneficiary, premise or credible alternative is missing. Preserve original IDs and overlap; do not force distinct count or write a made-up competitor.

If the considered set is inadequate for the choice, report the missing distinction and relevant `EXPLORATION_REQUIRED` / `OPTION_SET_INCOMPLETE` **under the governing policy**, rather than presenting a false binary. This is not permission to conduct every preceding Sensemaking stage; a narrow additional inquiry can be the correct stopping result.

## 3. Make two independent judgments

**A. Candidate-specific warrant: Why pursue this at all?**
State the few decision-critical prerequisites, source evidence and defeaters, the beneficiary/goal, consequences, uncertainty, currentness and authority. A candidate can be comparatively attractive but unwarranted now. Use the existing Warrant / Choice Policy; its `NO_SELECTION`, `MORE_EVIDENCE_REQUIRED`, `OWNER_DECISION_REQUIRED`, `CHALLENGE_REQUIRED`, `AUTHORITY_REQUIRED` and other dispositions are *semantic guidance*, not a new machine enum.

**B. Convergence rationale: Why this rather than a credible alternative?**
Compare targets at the same evaluative level under a declared frame. Explain meaningful differences, positive outcome, costs, uncertainty, possible adverse consequences, reversibility, omitted ends and deferral cost. A portfolio ranking can inform this judgment but does not establish it. Do not convert incomparable or not-assessed alternatives into the bottom ranks, or confuse a pairwise preference with global ordering.

Synthesis is permissible, not mandatory: if a composite option genuinely changes the desired end or consequences, describe the distinct combined outcome, conditional interaction, original constituents and newly incurred tradeoffs *before* assessing it. A list of positive features does not inherit the component candidates' benefits automatically.

## 4. Determine what kind of result actually occurred

| Result | What can be claimed | What must not be inferred |
| --- | --- | --- |
| **Evaluated / compared** | Alternatives and tradeoffs were examined | Winner or adoption |
| **Provisional preference / recommendation** | A source-attributed leading alternative exists under this frame | Actual owner decision or authorized execution |
| **Scoped selection** | A real actor with relevant authority adopted a typed target for a stated purpose/time, recording what it settles | New target identity, broader thesis change or automatic implementation |
| **NO_SELECTION / more inquiry** | Present evidence does not justify an actual target selection | A hidden failure, an imposed alternative or a universal negative judgment |
| **Reserved owner decision** | A choice depends on owner intent or ratification; provide bounded evidence or an owner-decision capsule | That the agent may decide for owner by guessing preference |
| **Option set incomplete** | A consequential grounded trajectory is missing from a contemplated owner packet | Forced binary choice or automatic stage reentry |

When a recommendation is truly within the owner's delegated **decision** authority, the active agent can make a bounded selection and cite the delegation. Otherwise report a recommendation or reserved decision. An owner request to **implement an ontology about selection** does not authorize the agent to select any of the product directions used as historical examples.

## 5. Describe selection scope and inheritance

For an actual selection, preserve in normal prose or the [optional record](convergent-direction-selection-record-template.md):

- decision date and real actor; where their authority comes from;
- original source-qualified typed target (not `selected:<new-copy>`);
- question/purpose, what it settles, what it explicitly leaves open;
- warrant and comparative rationale including accepted costs/contrary evidence;
- alternative dispositions (declined **for this purpose**, deferred, complementary, out-of-frame, unresolved, not assessed);
- any prerequisite another agent must recheck before acting, what observations might defeat the choice;
- which bounded continuation the selection guides, and which implementation, publication, merge or external actions still require independent authorization.

A valid existing decision permits later reasoning **within its scope**, without replaying all abandoned alternatives. If a genuinely decision-critical premise fails, reconsider the target and publish a new attributed interpretation; preserve the original. A stale file or new idea alone does not automatically reopen Level-3/4 strategy.

## 6. Compact source-based contrasts (no new decisions here)

**Historical convergence without adoption:** the 2026-11-03 Sensemaking convergence report identified different promising outcome directions but explicitly made **no** strategic/product selection.

**Historical recommendation:** the 2026-11-04 portfolio recommended owner-agency inquiry and articulated a Futures+Continuity proposition. It was a *recommended next intellectual inquiry*, not proof of owner adoption or implementation.

**Historical owner adoption:** ADR 0034 reports actual owner-ratified Level-4 product identity, its public entrypoint and authority boundary. That ratification applies only to the scope it states.

**Illustrative failure:** A is better than B within the compared set, but A's decisive prerequisite remains unsupported and B lacks permission. `NO_SELECTION` can be more justified than forcing A.

**Illustrative synthesis:** Combining idea X and Y is not an adopted new direction until distinct joint benefits, interactions, downside, source identity and competent decision authority are established.

## 7. Return evidence and stop

Return the bounded **decision question, compared source targets, candidate warrant, comparative rationale, actual recommendation/selection/nonselection status, any actor/authority, nonselected alternatives, critical unresolved premises, and stopping/continuation boundary**. Use existing strategic artifact, ADR, PR note, source report or receipt where durable state matters; a simple reversible choice can live in ordinary prose.

A specialist's choice *recommendation* returns to the active agent, which decides whether and how to continue within authority. A choice of direction never silently initiates Depth Exploration, code change, protected release, new Skill, source mutation or a different level of strategic governance.

**Selective memory:** existing v1 reviewed-knowledge kinds may retain declared concept definitions and source-document pointers when valuable; don't convert H1/H2 provisional rankings into `decision` claims, assert new executable `selects` relations or treat graph retrieval as truth.

**Portability:** this guide is self-contained. A target repository contributes its own sources and permissions, and does not need this framework checkout, `CLAUDE.md`, an SQLite index or the Sensemaking CLI.
