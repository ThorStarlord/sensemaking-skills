# Qualification — What this Skill can and cannot claim

Evidence levels are separate:

1. **Mechanical:** Skill entrypoint loads, references resolve, schemas validate, committed snapshots rebuild, source audit and queries behave predictably.
2. **Semantic:** A source-inspecting reviewer confirms a subset of authored concepts, decisions and implementation edges; record contradictions and uncertainty.
3. **Practical:** A genuine agent uses the knowledge in useful authorized engineering; record decisions and outcome, not merely invocation.
4. **Longitudinal:** A **fresh, independent** coding-agent context uses or corrects knowledge from an earlier episode. New Python process, synthetic roleplay or same-conversation replay is not sufficient.
5. **Comparative:** Evidence supports reduced rediscovery/rework or better decisions against a credible alternative, with honest confounds. Correct retrieval or increasing index counts alone is not comparative improvement.
6. **Transfer:** The process works on a second product with different repository conventions without special-case scaffolding overwhelming the value.

## Independent longitudinal lesson-use qualification (source-anchor example)

After the source-reviewed learning increments [#702](https://github.com/ThorStarlord/sensemaking-skills/pull/702) through [#705](https://github.com/ThorStarlord/sensemaking-skills/pull/705), the graph can mechanically return selected source-linked historical lessons. This is a new possible **authentic use** target, not a scheduled synthetic experiment or evidence that the later agent has already benefited.

**Trigger:** an actual separate coding agent has a worthwhile engineering responsibility involving knowledge queries, graph history, file-first re-entry, or provenance. Pin the checked-out target SHA, the installed and actually loaded Sensemaking Skill/reference revision, repository access and authority. Give it the ordinary product/development question and available governing sources. Do not put the expected `lesson:` IDs, our preferred answer, or this retrospective's conclusion in the agent's initial instruction.

**Observer/source-review responsibilities:** record which file/question initiated retrieval; the actual `context-for`, `search`, or direct source operations (when used); which historical lesson and original incident/revision were read; whether the agent checked current applicability and counterexamples; the specific observed change, narrowing or rejection in its engineering decision; the actual work/result and any authorization issues. Absence of retrieval or no impact is an informative outcome, not a reason to replay until success.

**Interpretation:** source-pinned query pass proves **mechanical reachability**; native Skill loading proves **availability**; a trace of reading the lesson proves **retrieval**; a source-backed material decision step may prove **decision use**; actual independent session identity and disjoint prior conversation sources are required for **longitudinal qualification**. A suitable credible alternative and explicit confound review are needed for **comparative improvement**. A declined inapplicable lesson can show correct application, while an uncritically followed stale lesson is negative evidence.

**Optional comparison:** only if it will affect a product decision, compare against a genuine source-only reconstruction with equivalent governing product sources; do not hide legitimate ordinary information or confuse different agent competence with a causal memory effect. Use existing S5/R6/R7 scopes and issue authorities, and retain source/PR evidence rather than creating another testing runtime. No second repository may be changed without explicit owner authorization.

If the executing environment lacks a genuinely separate coding-agent host, record `NOT EXECUTED — INDEPENDENT EXECUTOR UNAVAILABLE` and do not substitute a Python subprocess, CI job, ChatGPT continuation or a generated transcript.
