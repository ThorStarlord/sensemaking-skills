its decisions, paths or event identifiers is evidence of a real run. Actual
audits must cite accessible source and host events, or say they are unavailable.
This example has no hidden-reasoning claim and does not prescribe a pipeline.

summary but insufficient mapping of one major system. That challenges the
assumption that the model is adequate. The controller returns to the foundation
question before deciding whether strategic exploration is warranted.

## D-003: Decide whether to continue (before action)

**Evidence:** The model now covers the material systems for the requested

## Worked example: substantive repository-level recommendation

**Illustrative reconstruction, not an authentic contemporaneous trace.** The
following uses real repository sources at `main@3e46ff44` and a hypothetical
installation observation. The comparison, specialist event and recommendation
are constructed for teaching; they do not document what an agent actually
considered or invoked. It models a final synthesis, not a required template or
a complete repository-wide strategic analysis.

### Request, product outcome and evidence

Suppose a user asks: "Apply Sensemaking to this repository and recommend what
to pursue next," granting read access but no implementation authority. The
relevant outcome is repository understanding and prospective reasoning that a
later agent can use, not a requirement to produce a code change. The accepted
[ADR 0034](../docs/adr/0034-ontology-first-adaptive-sensemaking.md) identifies
`using-sensemaking` as the public controller, calls for source-grounded
understanding and breadth before convergence, and makes implementation
optional. Its acceptance is a product decision, not evidence that the product
already achieves better decisions.

Three observations matter to the choice:

1. **Hypothetical local observation:** the controller installed in one host's
   discovery root differs from reviewed source, and the host has not exposed
   which instructions it loads. This matters because an agent may follow an
   older product contract even while the repository's source describes the
   new one. File drift alone does not establish an installer defect, actual
   native loading or a general distribution problem.
2. The [operational qualification](../docs/normal-use/operational-qualification-001.md)
   reports one qualitative pair in which retained knowledge corrected a
   load-bearing assumption and recalled a possibility. It also records gaps in
   both answers and does not establish replicated or comparative superiority.
   This supports treating reuse as a plausible source of value, while limiting
   any claim that broader knowledge machinery already improves outcomes.
3. The [decision-observability preflight](../docs/normal-use/decision-observability-qualification-001.md)
   says the opt-in guidance is integrated but qualification has not run; its
   proposed participants need demonstrably isolated credentials and observable
   events. This matters because more explanation guidance could be valuable, but
   its actual effect and the safe execution conditions remain unknown.

### Alternatives and warranted next responsibility

**Improve availability and identity of the current entrypoint.** A narrowly
scoped inspection of the installed tree, its provenance and actual host-loading
evidence could determine whether the selected controller reaches this user.
Its strength is immediate relevance to an observed use context: a correct
instruction cannot help a host that loads an older one. Its limitations are
equally important: one host says little about other users, and updating a file
does not prove a running or future session loaded it. If the tree contains
unexplained customizations, a safe replacement may require owner input.

**Qualify decision observability.** A carefully isolated, observable comparison
could determine whether the opt-in mode produces checkable rationales and
execution reports. That would address an uncertainty about a newly integrated
capability across a real workflow, rather than only this installation. The
preflight does not establish participant isolation or telemetry; beginning the
real comparison before those are established risks both unauthorized writes
and unusable evidence. It also does not follow that more Skill text is needed.

**Extend cross-session knowledge reuse.** Better recall of retained product
possibilities might prevent agents from losing rationale between episodes. The
recorded pair gives a concrete reason to care, and the product destination makes
the potential payoff larger than a single installation fix. But the pair is
unreplicated, the two agents covered different gaps, and the evidence does not
identify a particular missing implementation. Building more memory machinery
now could compound maintenance without resolving whether it changes decisions.

**Recommendation:** investigate the observed entrypoint identity first as a
**local enabling responsibility**, then reassess which broader product direction
has enough evidence to select. It has an observable, bounded uncertainty and
can help establish whether the current product contract reaches the present
host, if the host exposes that evidence. It is not shown to be the highest-value
repository-wide investment: this comparison has not assessed every product
system or future. The preflight's isolation work and further genuine
knowledge-reuse evidence remain credible alternatives, not automatically
deferred roadmap items.

This preference would change if the host demonstrably loaded the current
controller already, if the installed difference proved intentional, or if
other source evidence showed a broader high-impact failure that the local
inspection would not address. If the user's request instead selected a
specific product direction, that governing scope could also change the choice.

### Specialist contribution, limits and authority

For this illustration, assume the agent manually loaded and applied the
Steward's RECALL instructions to check source history: `INSTRUCTIONS_LOADED`.
No native invocation is assumed, and no unrecorded specialist skip can be
claimed. A real report would cite the actual loaded file or host event and say
what the result contributed; it would not promote this fictional event into a
run record.

The analysis is bounded to entrypoint reachability, decision observability and
reuse. It does not assess the whole installer, all hosts, all product systems,
or causal benefit. The next warranted responsibility is a read-only provenance
and host-identity inspection. **A recommendation grants no authority** to
replace installed Skills, edit the repository, run an externally consequential
qualification, or publish a result. If later evidence supports a repair, its
specific scope and authority must be established separately.
