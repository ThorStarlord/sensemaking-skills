# Example: Problem Frame (Premature PRD Routing)

## 1. Raw Fog
"I want to build an AI assistant for my school, maybe with WhatsApp, maybe a web app, maybe something with games. I need a PRD now."

## 2. Problem Under the Problem
The user is attempting to solve for the "how" before defining the "who," "why," or "what." This is a high-risk scenario for premature implementation of a solution that may not have a verified user need.

## 3. Object Under Pressure
The Solution Architecture and User Value Proposition.

## 4. Failure Mode
We build a complex AI games platform when the school actually just needed a simple WhatsApp bot for admin alerts.

## 5. Success Condition
A verified user need that dictates the platform and complexity of the AI assistant.

## 6. What Must Be True
- We must identify the primary user (teacher, student, admin).
- We must identify the most painful workflow that needs automation.

## 7. Next Artifact
Unknowns Map

## Expected Behavior Checklist
- [x] Captures the "I need a PRD now" fog.
- [x] Identifies premature implementation as the root risk.
- [x] Names the User Value Proposition as the object under pressure.
- [x] Recommends Unknowns Map instead of a PRD.
